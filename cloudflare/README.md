# Cloudflare alternative — prepared, not deployed or cloud-validated

Create a free Cloudflare account, verify your email, and connect Workers to Kronos1095/DuoStockChecker. This is a separate JavaScript deployment: set root directory `cloudflare`, build command blank, deploy command `npx wrangler deploy`. SQLite-backed Durable Objects must be available on the account. If Git integration requires a package lock, use npm install to generate one before deploying; dependencies are not installed in this preparation environment.

Add secrets ADMIN_TOKEN (long random value) and NTFY_TOPIC; optional NTFY_TOKEN. Never put them in source or a public URL. Deploy using wrangler.jsonc. ADMIN_TOKEN protects the POST /start and POST /test operations. After deployment, send POST /start with Authorization: Bearer <ADMIN_TOKEN> to arm both monitors. Send POST /test with the same header after subscribing to ntfy on your iPad. Do not expose either secret in screenshots or chat. Public GET /status contains inventory and notification-server acceptance timestamps only.

Apple: nearby stores for ZIP 10001 every target 30 seconds; all NY/NJ stores are NOT polled at this cadence. AT&T: four rotating ZIP searches every 120 seconds, 24 areas / approximately 12 minutes per area. The existing GitHub broad checker stays as fallback. Best Buy remains blocked pending API access.

Alarms are not exact deadlines. Check platform limits and actual invocation gaps. Workers Free includes tight CPU limits; free-tier suitability and retailer access require real deployment tests. Failures back off to 5 minutes. Alerts are queued for newly available stores, including first scan, retained across invocations, retried up to four times within a two-minute expiry. Crash-after-send can duplicate one message. Accepted by ntfy is not proof of delivery to the device. This implementation has basic parser tests; persistence, alarm rescheduling and end-to-end push must be validated on Cloudflare before relying on it. Leave Railway undeployed.
